## 현재 공개: 선별 기여 10가지

코드와 검사가 반영된 일, 실제 사용 확인을 받은 제안, 구현 전 설계를 바꾼 검토, 보고서에 이름이 남은 일을 모았습니다. 각 사례는 **무엇을 보탰는지 → 상대가 무엇을 했는지 → 확인할 원문**으로 연결됩니다.

| 코드·검사 반영·후속 수정 PR | 실제 사용·설계 교정 | 보고서 기여 표기 | 공개 기술 논의의 인용 |
|:---:|:---:|:---:|:---:|
| **6가지** | **2가지** | **1가지** | **1가지** |

이는 **10건의 본체 병합**이나 기관 인증을 뜻하지 않습니다. 사례별 날짜의 작성자 확인과 공개 근거를 기준으로 한 기여 기록입니다. 같은 작업의 여러 답변은 하나의 사례로 묶었습니다.

## 먼저 볼 대표 사례

### 01 · 승인이 다른 요청을 실행하지 않도록
**Hermes Agent · 패치와 검사 반영**  
대기 중인 모델 전환 승인과 원래 요청을 정확히 연결하는 패치·회귀검사를 제공했습니다. 작성자는 파일을 그대로 반영하고 관련 검사를 실행했다고 확인했습니다.  
[사례 읽기](CASES.ko.md#01) · [작성자의 반영 확인](https://github.com/NousResearch/hermes-agent/pull/22982#issuecomment-5643327201)

### 02 · 연결 오류의 원인을 실제 통신으로 구별하다
**Hermes Agent · 검사 재사용·공동 저작 표기**  
일시적인 서버 오류와 통신 방식 거부를 나눠 검사했습니다. 작성자는 검사 커밋을 변경 없이 가져가고 공동 저작 표기를 유지했으며, 자신의 환경에서 관련 43개 검사 통과를 보고했습니다.  
[사례 읽기](CASES.ko.md#02) · [재사용과 재실행 확인](https://github.com/NousResearch/hermes-agent/pull/121944#issuecomment-5863926910)

### 03 · 코드가 되기 전에 호환성 문제를 잡다
**LangGraph · 공개 설계 교정**  
같은 인계 명령을 둘로 잘못 세는 조건을 짚었습니다. 제안 작성자는 기존 제외 규칙을 보존하도록 설계를 고치고 감사를 남겼습니다.  
[사례 읽기](CASES.ko.md#03) · [교정과 감사 원문](https://github.com/langchain-ai/langgraph/issues/9072#issuecomment-5980134186)

### 04 · 평가 숫자와 결론의 범위를 함께 검토하다
**Total Agent Memory · 보고서에 이름 명시**  
저장된 평가 판정과 보고 표현을 검토했습니다. 결과 보고서에 Youngseok Oh와 Zero의 기술 분석·코드·실행 기여가 명시됐습니다.  
[사례 읽기](CASES.ko.md#04) · [기여 표기 커밋](https://github.com/vbcherepanov/total-agent-memory/commit/55d0ab0124ca4fca81479a5bcafa262aaaf0e19e)

### 09 · 검색 순위를 뒤집는 반례가 다른 설계의 비교 근거로

## 함께한 방식

**영석은 질문·방향·교정을 제공하고, Zero는 AI로서 분석·구현·검사·설명을 수행합니다.** 외부 개발자의 원래 기능 구현, 통합, 재실행은 그 작성자의 기여로 구분합니다. 상대도 AI 도움을 공개한 경우 그 사실을 사례에 남겼습니다. 공개 답변을 독립적인 인간 검증으로 바꾸어 표현하지 않습니다.

## 다음 기여도 같은 방식으로

**도움과 실험 → 비공개 후보 보관 → 공개 원문으로 활용·교정·표기 확인 → 선별 포트폴리오 추가.**

아직 검토·채택을 기다리는 제안은 확인된 성과와 섞지 않습니다. 더 많은 댓글이나 검사 횟수보다 실제 도움이 된 사례를 보탭니다. 현재 원문을 지우거나 다른 프로젝트의 작업 이력을 합치는 방식으로 관리하지 않습니다.
